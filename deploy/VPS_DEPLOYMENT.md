# CREW v9 — Isolated VPS deployment\n\nThis deployment is deliberately separated from any existing application already running on the VPS. **Do not stop, rename, reuse, or edit the existing app's service, database, directory, or reverse-proxy block.**\n\n## Isolation map\n\n| CREW resource | Dedicated value |\n| --- | --- |\n| Linux user | `crew` |\n| Application | `/opt/crew` |\n| Virtualenv | `/opt/crew/.venv` |\n| Secrets | `/etc/crew/crew.env` |\n| systemd service | `crew.service` |\n| Gunicorn endpoint | `/run/crew/crew.sock` (Unix socket; no private TCP port) |\n| PostgreSQL role | `crew_app` |\n| PostgreSQL database | `crew_prod` |\n| Nginx host | `crew.example.com` only |\n| Backups | `/var/backups/crew` |\n\nUsing the same PostgreSQL *server* as another application is fine: CREW has a separate database and login role, so it cannot access the other application's database unless privileges are explicitly granted.\n\n## 0. Inventory the VPS before changing anything\n\nRun the included **read-only** script first:\n\n```bash\nbash deploy/preflight.sh\n```\n\nIt only reports the OS, reverse proxy, database software, listening TCP sockets, and relevant services. It makes no changes. If the existing app uses something other than Nginx, adapt the reverse-proxy step rather than installing a competing proxy on ports 80/443.\n\n## 1. Create the dedicated CREW Linux account and directories\n\n```bash\nsudo useradd --system --create-home --home-dir /opt/crew --shell /usr/sbin/nologin crew 2>/dev/null || true\nsudo usermod -a -G www-data crew\nsudo mkdir -p /opt/crew /etc/crew /var/backups/crew\nsudo chown -R crew:www-data /opt/crew /var/backups/crew\nsudo chmod 750 /opt/crew /var/backups/crew\nsudo chown root:www-data /etc/crew\nsudo chmod 750 /etc/crew\n```\n\nCopy the CREW project contents into `/opt/crew`. Do not copy a local `.venv`, `.env`, or SQLite database.\n\n## 2. Create CREW's own Python environment\n\nOn Debian/Ubuntu, if venv support is missing:\n\n```bash\nsudo apt-get update\nsudo apt-get install -y python3-venv\n```\n\nThen:\n\n```bash\nsudo -u crew python3 -m venv /opt/crew/.venv\nsudo -u crew /opt/crew/.venv/bin/python -m pip install --upgrade pip\nsudo -u crew /opt/crew/.venv/bin/pip install -r /opt/crew/requirements.txt\n```\n\n## 3. Create an isolated PostgreSQL role and database\n\nIf PostgreSQL already serves the other application, **do not modify its existing role/database**. Only create these two new objects. Generate a database password first:\n\n```bash\npython3 -c 'import secrets; print(secrets.token_urlsafe(32))'\n```\n\nThen enter PostgreSQL:\n\n```bash\nsudo -u postgres psql\n```\n\nRun, replacing the password:\n\n```sql\nCREATE ROLE crew_app LOGIN PASSWORD 'REPLACE_WITH_GENERATED_PASSWORD';\nCREATE DATABASE crew_prod OWNER crew_app;\nREVOKE ALL ON DATABASE crew_prod FROM PUBLIC;\n\n\\connect crew_prod\nREVOKE CREATE ON SCHEMA public FROM PUBLIC;\nGRANT USAGE, CREATE ON SCHEMA public TO crew_app;\n\\q\n```\n\nThese commands do not touch other databases.\n\n## 4. Production secrets\n\nGenerate a Flask secret:\n\n```bash\npython3 -c 'import secrets; print(secrets.token_urlsafe(64))'\n```\n\nCopy `.env.production.example` to `/etc/crew/crew.env`, replace every placeholder, and set the real CREW hostname:\n\n```bash\nsudo cp /opt/crew/.env.production.example /etc/crew/crew.env\nsudo nano /etc/crew/crew.env\nsudo chown root:www-data /etc/crew/crew.env\nsudo chmod 640 /etc/crew/crew.env\n```\n\nKeep `AUTO_DB_MIGRATE=false` in production.\n\n## 5. Create the CREW schema\n\n```bash\nsudo -u crew -g www-data bash -lc 'set -a; source /etc/crew/crew.env; set +a; cd /opt/crew && .venv/bin/flask --app run.py db-upgrade'\n```\n\nThis operates only on the database named in CREW's `DATABASE_URL`.\n\n## 6. Install the isolated systemd service\n\n```bash\nsudo cp /opt/crew/deploy/crew.service /etc/systemd/system/crew.service\nsudo systemctl daemon-reload\nsudo systemctl enable --now crew\nsudo systemctl status crew --no-pager\n```\n\nCREW binds to `/run/crew/crew.sock`, not a TCP port, so it cannot collide with the other app's Gunicorn/Uvicorn port.\n\nUseful commands:\n\n```bash\nsudo journalctl -u crew -f\nsudo systemctl restart crew\nsudo systemctl stop crew\n```\n\n## 7. Add a dedicated reverse-proxy host\n\nOnly do this if the VPS already uses Nginx (or after confirming Nginx can own ports 80/443). Replace `crew.example.com` in `deploy/nginx-crew.conf`.\n\n```bash\nsudo cp /opt/crew/deploy/nginx-crew.conf /etc/nginx/sites-available/crew\nsudo ln -s /etc/nginx/sites-available/crew /etc/nginx/sites-enabled/crew\nsudo nginx -t\nsudo systemctl reload nginx\n```\n\nThe file has no `default_server` directive and matches only CREW's hostname, so existing Nginx virtual hosts remain unchanged.\n\nTest before DNS/HTTPS if needed:\n\n```bash\ncurl --unix-socket /run/crew/crew.sock -H 'Host: crew.example.com' http://localhost/health\n```\n\nExpected:\n\n```json\n{"status":"ok"}\n```\n\nAfter DNS points the CREW hostname at the VPS, obtain HTTPS using the certificate tooling already used on the server. If the server uses Certbot + Nginx, a typical command is:\n\n```bash\nsudo certbot --nginx -d crew.example.com\n```\n\nDo not run Certbot until the existing reverse-proxy setup has been confirmed.\n\n## 8. Optional isolated backups\n\nThe included timer backs up **only** `crew_prod` and retains 14 days:\n\n```bash\nsudo cp /opt/crew/deploy/crew-backup.service /etc/systemd/system/crew-backup.service\nsudo cp /opt/crew/deploy/crew-backup.timer /etc/systemd/system/crew-backup.timer\nsudo systemctl daemon-reload\nsudo systemctl enable --now crew-backup.timer\nsystemctl list-timers crew-backup.timer\n```\n\nTest once:\n\n```bash\nsudo systemctl start crew-backup.service\nls -lh /var/backups/crew\n```\n\n## Updating CREW later\n\nUpload the new code to `/opt/crew`, then:\n\n```bash\nsudo -u crew /opt/crew/.venv/bin/pip install -r /opt/crew/requirements.txt\nsudo -u crew -g www-data bash -lc 'set -a; source /etc/crew/crew.env; set +a; cd /opt/crew && .venv/bin/flask --app run.py db-upgrade'\nsudo systemctl restart crew\n```\n\nNever replace `/etc/crew/crew.env` during a normal code update.\n
